# README Style Guide

## Reference Projects

Use the following repositories as style references only:

- https://github.com/AhmadALSaffan/Neon-Nior
- https://github.com/AhmadALSaffan/BANK-AL-DEIR

## Required Approach

- Inspect the current repository before writing or updating a README.
- Match the references' general product-focused presentation, visual clarity, Markdown hierarchy, readability, feature presentation, spacing, and polished portfolio quality where suitable.
- Adapt the structure to the actual project rather than copying it blindly.
- Use clear title, concise product description, verified features, verified stack, copy-ready setup, and relevant visuals only when they exist.
- Include only sections that are useful and supported by verified project information.
- Keep the README accurate for both users and developers.

## Never Do

- Never copy project-specific content from reference projects.
- Never invent features, commands, dependencies, environment variables, screenshots, URLs, badges, metrics, testimonials, licenses, author information, or deployment details.
- Never expose secrets, private endpoints, credentials, internal URLs, or sensitive architecture details.
- Never leave stale setup steps, dead links, or inaccurate feature claims.

## Verification

- Verify commands against build files, package files, scripts, CI workflows, and project configuration.
- Verify every link, path, image, code block, badge, environment variable, and technology claim.
- Verify that listed features exist in the project.
- Omit unavailable information or clearly mark it as TODO instead of guessing.
