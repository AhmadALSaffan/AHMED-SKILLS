# Project Initialization Checklist

Use this checklist during `/ahmed-skill init`. Inspect the repository first and ask only for information that cannot be verified.

## Product

- Project name
- One-sentence product description
- Problem being solved
- Primary users
- Main user job or primary action
- Product goal and success criteria
- MVP scope
- Non-goals

## Platform and Stack

- Target platform: Android, web, backend, desktop, full-stack, or other
- Existing repository status: new, partial, or established
- Preferred or existing technologies
- Required integrations: auth, payments, maps, AI, analytics, notifications, storage, etc.
- Supported devices, browsers, OS versions, and locales

## Design

- Design direction, brand personality, and emotional tone
- Dark, light, adaptive, or custom theme preference
- Brand colors, logo, typography, and existing design assets
- Visual references and what to learn from them
- Explicit anti-references: patterns or styles to avoid
- Accessibility, localization, RTL, and responsive requirements

## Engineering

- Architecture preference or existing architecture
- Data sources, APIs, database, cache, and offline requirements
- Authentication and authorization requirements
- Security and privacy requirements
- Performance and cost constraints
- Testing expectations
- Deployment target and environment strategy

## Delivery

- Priority and deadline
- Required milestones
- Definition of done
- Release or review process
- Known risks, technical debt, blocked decisions, and dependencies

## Files To Create or Update

Create only what is applicable and supported by known information:

- `CLAUDE.md`
- `docs/project-brief.md`
- `docs/design-direction.md`
- `docs/architecture.md`
- `README.md`
- Feature specifications or ADRs

## Final Init Output

After discovery, provide:

1. Verified project summary.
2. Unresolved questions and assumptions.
3. Design direction or design discovery questions.
4. Proposed architecture and folder structure.
5. MVP implementation phases.
6. Testing and quality plan.
7. First recommended implementation task.
