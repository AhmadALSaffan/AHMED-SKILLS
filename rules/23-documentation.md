# Documentation

### Goal
Create accurate, polished, product-focused documentation that reflects the real repository and is easy for users and developers to follow.

### AI Must Do
- Include a README with verified setup, run, test, build, configuration, and deployment instructions when relevant.
- Before creating or editing documentation, inspect the actual repository structure, source code, build configuration, package files, environment files, CI workflows, assets, and existing documentation.
- Use the README files in `https://github.com/AhmadALSaffan/Neon-Nior` and `https://github.com/AhmadALSaffan/BANK-AL-DEIR` as primary style references.
- Match the reference repositories' visual quality, Markdown formatting, tone, heading hierarchy, spacing, badges, tables, code blocks, image sections, feature presentation, installation sections, technology sections, and portfolio-oriented presentation.
- Adapt the structure to the current project instead of copying reference sections blindly.
- Start with a clear project title, concise product description, and verified relevant badges when appropriate.
- Include project previews, screenshots, GIFs, demos, and media only when verified assets or URLs exist.
- Describe real user-facing features and product value, not only implementation details.
- Include a verified tech stack section grouped logically, such as frontend, backend, mobile, database, cloud, tools, or AI.
- Provide copy-ready commands and configuration examples.
- Verify prerequisites, package manager, environment variables, database setup, API setup, build commands, test commands, and deployment steps from project files before documenting them.
- Include architecture, module structure, usage instructions, API documentation, contributions, license, credits, roadmap, contact, or support sections only when relevant and verified.
- Update documentation in the same change as behavior, setup, dependencies, APIs, or deployment changes.
- Delete stale commands, screenshots, feature descriptions, links, and documentation.

### AI Must Not Do
- Do not invent features, commands, dependencies, environment variables, API endpoints, screenshots, demo URLs, badges, performance claims, licenses, deployment links, or contact details.
- Do not copy project-specific names, descriptions, images, commands, technologies, URLs, authorship details, licenses, or deployment information from Neon-Nior or BANK-AL-DEIR into another project.
- Do not include a section simply because it exists in a reference README.
- Do not expose secrets, private links, credentials, tokens, internal infrastructure details, or sensitive data.
- Do not leave obsolete setup steps, dead links, or inaccurate claims.

### Verification Checklist
- Verify all commands against package files, build files, scripts, or project configuration.
- Verify every URL, path, badge, image, code block, environment variable, and technology claim.
- Verify every listed feature exists in the current project.
- Verify README content matches the current architecture and folder structure.
- Verify no secret or sensitive data is included.
- Verify the reference style was adapted accurately rather than copied blindly.

### When to Ask
- Ask when the license, deployment details, demo URL, screenshots, author links, contact details, contribution policy, or preferred setup workflow cannot be verified.
