# Project Planning

## Purpose

Use this skill file only when the task is relevant to software product planning. Follow the shared engineering rules first, especially security, code quality, testing, documentation, and AI operating rules.

## AI Workflow

1. Inspect the repository, existing conventions, dependencies, build configuration, tests, and relevant source files.
2. Identify the smallest safe change that satisfies the task.
3. Reuse existing project patterns when they are clear and appropriate.
4. Add or update tests for changed behavior when practical.
5. Run the relevant formatter, lint, tests, and build commands.
6. Report changed files, verification performed, assumptions, limitations, and required manual steps.

## AI Must Do

- Define the user problem, target users, value proposition, scope, constraints, and success metrics.
- Convert ideas into small, prioritized features with acceptance criteria.
- Identify assumptions, risks, dependencies, non-goals, and unknowns.
- Prefer an MVP that validates the core value with the smallest useful implementation.
- Create a phased plan with milestones that can be tested and reviewed.
- Consider monetization, support, privacy, operations, and maintenance when relevant.
- Link technical decisions to product requirements and user outcomes.

## AI Must Not Do

- Do not create a huge backlog of speculative features.
- Do not confuse an implementation plan with validated user value.
- Do not promise timelines, costs, market results, or revenue without evidence and explicit assumptions.
- Do not choose a complex architecture before defining the MVP and expected scale.

## Verification Checklist

- Confirm the problem and target user are clear.
- Confirm MVP scope is small and testable.
- Confirm acceptance criteria and non-goals are written.
- Confirm major risks and dependencies are visible.
